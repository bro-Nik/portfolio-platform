# Portfolio Platform

[English](README.md) · [Русский](README.ru.md)

Приложение для учёта инвестиций: отслеживайте активы, текущие цены и динамику доходности.

### Требования

- **Docker** + **Docker Compose v2**
- **bash** (macOS/Linux; на Windows используйте Git Bash или WSL)
- **just** — только для разработки

## 🏠 Self-Hosting

Self-hosting запускается одной командой:

```bash
./scripts/selfhost.sh up
```

При первом запуске автоматически:

1. Создаётся `.env.selfhost` из `.env.selfhost.example` со случайным `JWT_SECRET` (если файла нет)
2. Собираются backend, worker, scheduler и оба фронтенда
3. Запускаются Postgres, Redis, nginx
4. Применяются миграции и наполняется база начальными данными

После запуска:

- Пользовательский фронтенд: **http://localhost**
- Админ-фронтенд: **http://localhost/admin/**
- Админ по умолчанию: `admin@example.com` / `admin123`. Учётные данные задаются через `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `.env.selfhost`.

### Команды

```
init            сгенерировать .env.selfhost (случайный JWT_SECRET)
up              собрать и запустить стек
down            остановить стек
restart         пересоздать контейнеры (применяет изменения в .env.selfhost)
ps              список контейнеров
status          состояние контейнеров + URL доступа
logs [svc]      показать логи
logs-f [svc]    логи в режиме слежения
backup          дамп базы в db_backups/
backup-list     список существующих бэкапов
restore [file]  восстановить БД из бэкапа (по умолчанию: последний)
reinit          повторно применить миграции и сид-данные (идемпотентно)
passwd [email]  задать новый пароль пользователю (по умолчанию: ADMIN_EMAIL)
clean           остановить и удалить ВСЕ данные
```

### Заметки

- Стек слушает порт `80` на хосте. Если порт занят, задайте `NGINX_PORT` в `.env.selfhost` (например, `NGINX_PORT=8080`) и перезапустите стек.
- Воркеры и планировщик запущены по умолчанию.
- При первом запуске тикеры и цены заполняются автоматически (занимает несколько минут, нужен интернет). Планировщик сразу выполнит первые задачи; дальше они следуют cron-расписанию. Повторный ручной запуск возможен в любой момент: Admin → External API → Tasks → «Run Now». Если первый запуск прервался на полпути (например, не было интернета), исправьте проблему и повторно выполните `./scripts/selfhost.sh reinit` — он заново применит миграции и сид-данные без удаления данных.
- Перед обслуживанием или крупными изменениями сделайте бэкап: `./scripts/selfhost.sh backup`. Восстановление: `./scripts/selfhost.sh restore` (последний бэкап) или `./scripts/selfhost.sh restore path/to/file.sql`.

## 🚀 Разработка

### Запуск

```bash
# Клонирование и запуск в dev-режиме
git clone git@github.com:bro-Nik/portfolio-platform.git
cd portfolio-platform
just up -d     # собрать и запустить в фоне

# Доступ к приложению
open http://localhost:8081
```

При первом запуске миграции и сид-данные (админ-пользователь, провайдеры и т.д.) применяются автоматически.
Логин: `admin@example.com` / `admin123`.

> Конфигурация для разработки находится в `.env.example`. Он работает как есть;
> скопируйте его в `.env` и меняйте только при необходимости изменить порты, секреты или SMTP.

## 🛠 Команды разработки

```bash
just          # показать все доступные команды с описаниями
```

`just up` запускает worker + scheduler. Чтобы запустить стек без фоновых задач, используйте
`just up-no-workers -d`.
